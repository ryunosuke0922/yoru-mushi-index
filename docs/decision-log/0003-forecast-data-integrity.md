# 0003. Forecast data integrity and uncalibrated scores

| Item   | Value      |
| :----- | :--------- |
| Status | Accepted   |
| Date   | 2026-11-12 |

## Context

取得失敗時に固定の夏季相当の気象値を使い、欠測値を0へ置換していたため、利用可能な予報と架空・不完全な入力を区別できなかった。直近24時間雨量は参照時刻を除外して23個の時間雨量になり、観察区間の雨・突風も公式の「直前1時間」という定義とずれていた。さらに、手作業のスコアを百分率の見込みとして表示すると校正済みの出現確率に見える。

## Options

1. 代替気象を残し注記する。表示は続けやすいが、実際の天気に基づかない指数を生成する問題は残る。
2. 利用可能な入力だけで計算し、欠測・算出不可・未校正を明示する。
3. 直ちに学習モデルへ置き換える。目的変数と観察努力を揃えたデータがなく、性能を検証できない。

## Decision

選択肢2を採用する。`heuristic-v0.2` では次を行う。

- 代替気象を生成せず、0時間帯なら `unavailable`、1-4時間帯なら `partial`、5時間帯なら `available` とする。
- 算出不可では `score` / `label` / `bestTime` / `taxa` / `condition` を `null` とし、0点の悪条件と区別する。
- 欠測・不正値は項目ごとに判定し、その値を必要とする区間を除外する。24時間の雨量履歴が揃わなければ集計関数は `null` を返し、その観察時間帯を算出しない。
- `t` から1時間の区間では瞬時値を `t`、雨・突風を終端 `t+1h` から取る。直近雨量は `(t-24h, t]` の24値を使う。
- `dataSource` / `modelVersion` / `calibration` を返す。`generatedAt` は計算時刻であることを文書化する。
- 確率表示を廃止する。API の `probabilityBand` は互換用に常に `null` とする。
- 雨・風の既存の閾値を使った最終上限を総合・分類別に適用し、気温上限も分類別に適用する。上限は未検証の保守的な表示規約と明記する。

根拠となるAPI仕様と一次研究は [research-evidence.md](../research-evidence.md)、具体的な閾値は [scoring.md](../scoring.md) を参照する。

## Consequences

利用者・API利用者は、天気の悪さとデータの不在を区別できる。部分予報のおすすめ時間は、存在する時間帯の範囲内の比較である。API利用側には新しい状態とnullable値への対応が必要になる。

入力・境界条件の修正はテストで確認するが、実際の虫の観察に対する予測性能は未検証のままである。エリア別の平年気温による季節係数、固定19-23時、分類群・観察方法・地域の差は未解決論点として残す。詳細地点を新たに収集せず、粗いエリアの観察努力・0件を含むログで将来比較する。

完了条件は既定の format、typecheck、lint、test、build と、取得失敗・部分欠測・時間区間・24時間集計・雨風上限・位置情報非公開の検証とする。検証結果は実行した時点の結果で報告し、このADR自体を合格の記録にはしない。
