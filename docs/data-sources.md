# Data Sources

## Weather

天気予報は Open-Meteo API の hourly forecast を利用します。
公式仕様: [Weather Forecast API](https://open-meteo.com/en/docs)。

取得範囲:

- 対象日の19:00-20:00から23:00-翌00:00までを時間別スコアの対象にする
- 直近24時間雨量と最終区間の計算に使うため、対象日の前日から翌日までを取得する
- 7日予報では、起点日の前日から最終予報日の翌日までを1回の Open-Meteo request で取得する

利用変数:

- `temperature_2m`: 気温。総合スコア、理由表示、甲虫補正に使用する。
- `relative_humidity_2m`: 湿度。総合スコアと理由表示に使用する。
- `precipitation`: タイムスタンプで終わる直前1時間の合計降水量。観察時間中の雨による減点に使用する。
- `wind_speed_10m`: 風速。弱風の加点、強風の減点に使用する。
- `wind_gusts_10m`: タイムスタンプで終わる直前1時間の最大突風。突風による減点に使用する。
- `cloud_cover`: 雲量。月明かりの見え方を弱める補正に使用する。

風速は `wind_speed_unit=ms` を指定し、アプリ上では `m/s` として表示します。
Open-Meteo への取得は 1 時間キャッシュします。
画面の条件は、算出できた観察時間帯のうちスコアが最も高い時間帯に対応します。

### 区間の対応

Open-Meteo の気温・湿度・風速・雲量は時刻の瞬時値、降水量・突風は直前1時間の集計です。19:00-20:00を評価する場合、瞬時値は19:00、雨量・突風は20:00の値を使います。23:00-翌00:00には翌日00:00の集計値を使います。

開始時刻 `t` までの直近24時間雨量は、`t-24h < timestamp <= t` の24個の時間雨量の合計です。現在の観察区間 `(t, t+1h]` の雨量は含みません。1時間ごとの履歴が揃わなければ集計関数は `null` を返し、その観察時間帯を算出対象から除外します。公開される時間帯の直近雨量は数値です。

### 欠測・不正値

欠測、非数値、非有限値、範囲外の値を項目ごとに判定します。開始時刻の気温・湿度・風速・雲量、終端の雨量・突風、直近24時間の雨量がすべて揃った区間を採点します。たとえば昼の湿度が欠けても、その時刻の雨量は履歴に使えます。

### モデルと精度の範囲

汎用 Forecast API の Best Match は日本では JMA MSM を含むモデルを組み合わせ、変数や予報期間の不足を他モデルで補います。[JMA API](https://open-meteo.com/en/docs/jma-api) の MSM は約5km格子ですが、JMA のネイティブ出力には突風がありません。JMA 固定化だけで精度が上がるとは判断せず、必要変数を確認して比較します。

標高補正に使われる地形データの解像度と、気象予報モデルの格子間隔は別です。代表座標の予報は広域全体や林内の微気象を保証しません。モデルの比較・過去予報の使い分けは [research-evidence.md](research-evidence.md) を参照してください。

## Moon

月条件は SunCalc で計算します。

利用値:

- 月照度: 月明かりの影響判定に使用する。
- 月高度: 月が地平線より上にあるかの判定に使用する。
- 月相: 取得条件として表示する。総合スコアには直接渡していない。

スコア計算では、月が地平線より上にあり、照度が高く、雲量が少ない場合に月明かりの影響を大きく見ます。月相は取得条件として表示します。

## 気候平年値

気象庁の「アメダス（地域気象観測）月・年別平年値」と同版の地点情報を加工しています。統計期間が1991〜2020年の30年で、気温の月平均（要素0500）が12か月すべて正常値（品質8）の地点を使います。[気象庁の配布元](https://www.data.jma.go.jp/stats/data/mdrr/normal/index.html)

各エリアの内部代表点から球面距離20km以内の該当地点を月ごとに単純平均し、最も近い整数℃に丸めています。該当地点がない4エリアは最寄りの有効地点を採用しました。離島など広い範囲を含むエリアでは代表点周辺の概算です。集計した12か月分を同梱し、予報時に外部取得は行いません。

## Area

エリアは `packages/area/src/areaFixtures.ts` の広域 fixture を使います。

内部利用値:

- `latitude` / `longitude`: Open-Meteo と SunCalc の計算に使う代表座標。公開 API には返さない。
- `seasonScore`: エリアごとの季節適性。総合スコアに加点する。
- `monthlyMeanTemperaturesC`: エリアごとの1〜12月の月平均気温平年値。予報日の月別補正に使う。
- `habitatScore`: 広域環境による補正。総合スコアと分類別スコアに使う。

公開値:

- `id`
- `name`
- `region`
- `prefecture`
- `precision`
- `precisionKm`
- `locationPolicy`

## 取得失敗と利用可能性

Open-Meteo の取得失敗時は `status: unavailable` とし、指数と条件を `null` にします。表示継続用の架空の fallback weather は使用しません。一部の時間帯だけ算出できる場合は `partial`、全5時間帯を算出できる場合は `available` とします。

`generatedAt` は指数の計算時刻です。気象モデルの発表時刻ではなく、キャッシュの経過時間も表しません。`dataSource` / `modelVersion` / `calibration` の規約は [api-design.md](api-design.md)、判断の理由は [ADR 0003](decision-log/0003-forecast-data-integrity.md) に記載します。
